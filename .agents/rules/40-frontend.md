# Frontend Rules

- `frontend/` is a real TanStack Start app (React + Vite, file-based routing), not an empty scaffold. Read `frontend/README.md`, `frontend/package.json`, `frontend/AGENTS.md`, and `bun.lock` before editing it.
- MUST use `bun`/`bunx` for every frontend command, run from the `frontend/` directory. `frontend/bun.lock` is the dependency source of truth. MUST NOT use `npm`, `npx`, `pnpm`, `pnpm dlx`, or `yarn`.
- MUST run frontend scripts with the `--bun` runtime flag (`bun --bun run dev|build|lint|format|check`) because the app targets Bun. One-off tools use `bunx` (e.g. `bunx --bun @better-auth/cli secret`).

## Agent skills (Intent)

- MUST follow `frontend/AGENTS.md`: before a substantial frontend change, run `bunx --no-install --package @tanstack/intent intent list` from `frontend/`, and load a matching skill with `bunx --no-install --package @tanstack/intent intent load <package>#<skill>`.
- MUST use the installed Intent only; do not download a replacement or invent skill names.
- Prefer the most specific local skill for the package being changed; load another only when the task spans multiple concerns.

## Framework conventions (TanStack Start)

- TanStack Start is NOT Next.js: no `"use server"`, `getServerSideProps`, or `app/layout.tsx`. Code is isomorphic by default; keep DB access, secrets, and API keys in `createServerFn` / server routes and never expose them with a `VITE_` prefix.
- `tanstackStart()` MUST be the first Vite plugin (before `viteReact()`). `tsconfig.json` already enables `verbatimModuleSyntax` — do not flip it; it is part of the scaffold's strict type mode.
- Routes live in `src/routes/` (file router). `src/routeTree.gen.ts` is generated — do not hand-edit; regenerate with `bun --bun run generate-routes` or a dev/build.
- The root route document shell (`src/routes/__root.tsx`) must render `HeadContent`, `Outlet`, and `Scripts` (with `Scripts` in `<body>`).
- Types are fully inferred: do not cast or annotate inferred values.
- MUST use arrow function expressions for all functions in `src/`, `tests/`, `e2e/`, and config files. MUST NOT use `function` declarations or `export function`. For a named default export, declare `const Name = () => ...` then `export default Name`. Exempt: `src/components/ui/**` (shadcn scaffold keeps `function` declarations) and generated output (`src/paraglide/**`, `src/routeTree.gen.ts`).
- Use `createServerFn` for server-only work and call it directly from route loaders rather than self-fetching `/api/...`. Enforce auth in the server function or middleware, not only in `beforeLoad`.
- MUST use `axios` for backend HTTP calls inside server functions. Create one configured instance with `baseURL`, `timeout`, and `paramsSerializer`; do not use raw `fetch` for backend calls. Use native `fetch` only for non-backend platform APIs. Pass the backend JWT as `Authorization: Bearer <token>` per request.

## Add-ons already wired

- Auth: Better Auth, Google-only (`src/lib/auth.ts`, `src/lib/auth-client.ts`, catch-all `src/routes/api/auth/$.ts`). No email/password login; no `emailAndPassword` plugin, no password fields in schemas. Validate Google sign-in with `googleSignInSchema` from `src/validation/auth.ts`.
- Data: TanStack Query provider in `src/integrations/tanstack-query/`, TanStack DB collections in `src/db-collections/`, TanStack Store, TanStack Table v9, TanStack Form, React Compiler.
- Env: T3Env in `src/env.ts`; client-safe vars use the `VITE_` prefix.
- UI: Tailwind CSS v4 + shadcn/ui (`components.json`, `src/components/ui/`), mobile-first. Prefer shadcn components over bespoke widgets.
- i18n: Paraglide — messages in `project.inlang/messages`, generated output in `src/paraglide/` (do not hand-edit; regenerated by dev/build). The generated READMEs use `bunx --bun` via Bun patches in `frontend/patches/` (`@inlang/paraglide-js`, `@inlang/sdk`); `scripts/normalize-i18n-docs.mjs` is a safety net run on install/dev/build. Regenerate the patches when upgrading those packages.
- AI: TanStack AI (`chat()`, `openaiText()`, adapters). Do not use Vercel AI SDK patterns such as `streamText` or `createOpenAI`.

## Gate and API contract

- The frontend gate is separate from `scripts/gate.py`: run `bun --bun run typecheck`, `bun --bun run lint`, `bun --bun run check`, `bun --bun run test`, `bun --bun run test:e2e`, and `bun --bun run build` from `frontend/`. Never add a TypeScript gate to `scripts/gate.py`.
- The frontend consumes the backend contract in `docs/API.md`. When a backend route/schema/auth/status-code changes, update the frontend consumer in the same change; do not change the backend contract to suit UI code without updating `docs/API.md`.
- MUST treat backend responses as the only source of truth for displayed data. Do not hardcode domain data (providers, models, prices, status, counts) in `src/`. UI-only constants (labels, dials, nav labels) are allowed. If the backend lacks an endpoint, add one and update `docs/API.md` plus the `README.md` API table before using it.
- Keep frontend secrets in `frontend/.env.local` (gitignored); never commit keys.

## Queue and E2E stubs

- Render queue is RabbitMQ via `amqplib` in `src/server/queue.ts`; queue name `shorts-render`. MUST NOT reintroduce BullMQ/ioredis/Redis.
- `RABBITMQ_URL` is server-only in `src/env.ts`; never prefix it with `VITE_`.
- The AMQP worker entry is `workers/render-worker.ts` (`bun --bun run worker:render`); it calls `backend/scripts/render_job.py`, not the Taskiq task directly.
- MUST stub TanStack Start server functions in Playwright with `frontend/tests/helpers/server-fn.ts`: header `x-tss-serialized: true` plus `toJSONAsync(...).t` tree. Do not hand-roll raw JSON stubs in specs.
- MUST use `mockApiGet(page, path, value)` for `apiGet` GET calls; the path lives in the `payload` query parameter, not the body.

## Layout additions

- `src/type/` — TypeScript types and interfaces (e.g. `src/type/auth.ts`).
- `src/validation/` — Zod schemas for request/response validation.
- `tests/` — Vitest unit/component tests (`*.test.ts|tsx`), setup in `tests/setup.ts`, config in `vitest.config.ts`.
- `e2e/` — Playwright end-to-end tests (`e2e/*.spec.ts`), config in `playwright.config.ts`.
